Autonomous QC and Anomaly Detection for Omics Pipelines

January 2025 15 min read
Bioinformatics Agentic AI Machine Learning Python

Introduction

I built an autonomous QC layer on top of omics pipelines that continuously ingests pipeline QC metrics, learns baseline behavior per assay and pipeline step, and automatically flags outliers. The system traces anomalies back to specific tools, parameters, or batches and recommends remediation actions (reruns, parameter changes, or sample exclusion), reducing debugging time and preventing silent QC failures in production workflows.

In this post, I'll walk through the design and implementation of a lightweight v1 system that you can actually build and deploy. We'll cover the core components, implementation details, and provide concrete code examples.

System Overview

The system consists of three main components working together:

  1. QC Metrics Collector - Normalizes and stores QC metrics from pipeline runs
  2. QC Anomaly Detector - Learns baseline patterns and flags outliers using robust statistics
  3. Explanation & Remediation Recommender - The agentic layer that reasons over anomalies and proposes actions
Scope for v1: To keep this simple but impactful, we'll constrain v1 to one assay type (e.g., bulk RNA-seq), one pipeline (your existing Airflow or Nextflow RNA-seq pipeline), and a manageable set of QC metrics collected per sample and per step.

QC Metrics: What to Collect

For a v1 implementation focused on RNA-seq, here are the key QC metrics to track:

Per Sample Metrics

  • Total reads, mapped reads, % mapped
  • % duplicates
  • % rRNA / % mitochondrial reads
  • Insert size mean / std
  • GC content
  • Number of detected genes
  • 5'–3' coverage bias (if available)
  • Library complexity estimates (optional)

Per Pipeline Step Metrics

  • Runtime, exit status, memory usage
  • Tool name + version (e.g., STAR 2.7.10a, fastp 0.23.3)

System Design: Core Components

1. QC Metrics Collector

Goal: Normalize all QC metrics into a single table or DataFrame.

Schema (conceptual):

  • sample_id
  • batch_id
  • assay_type (e.g., rna_seq)
  • pipeline_step (e.g., alignment, trimming, qc_summary)
  • tool_name, tool_version
  • metric_name (e.g., pct_mapped, duplication_rate)
  • metric_value (numeric)
  • run_timestamp

Implementation: At the end of each major step in your Airflow DAG, add a small task that:

  • Parses QC outputs (FastQC, Picard, STAR logs, etc.)
  • Writes metrics into a central store: e.g., a Postgres table, a Parquet file in object storage, or a qc_metrics.csv that you append to

2. QC Anomaly Detector

Goal: Learn "what's normal" for each metric and flag outliers per new run.

For v1, we'll use a simple and robust approach:

Group by: (assay_type, pipeline_step, metric_name)

For each group:

  • Use robust statistics to get baseline:
    • Median: m
    • Median Absolute Deviation (MAD): MAD
  • For a new metric value x, compute a robust z-score: 
    z = (x - m) / (1.4826 * MAD + ε)
  • Flag anomalies where |z| > z_threshold (e.g., 3)

You can also add per-batch comparison: compare a new batch's distribution vs historical distribution. Optionally, use IsolationForest or similar if you want ML-based anomaly detection.

3. Explanation & Remediation Recommender (Agentic Layer)

This is where you add "agentic" behavior: reasoning over anomalies and proposing actions.

v1 can be rules + templated output; v1.5 can add an LLM. The rule-based approach creates a simple mapping from (metric_name, direction) → likely_cause, suggested_action.

Example mappings:

  • pct_mapped very low → Causes: wrong reference, contamination, sample swap. Actions: verify reference build, check sample sheet, re-run alignment with stricter QC.
  • duplication_rate very high → Causes: low input, over-amplification, library prep issues. Actions: review library prep batch, consider excluding sample or re-sequencing.
  • pct_rRNA very high → Causes: failed rRNA depletion. Actions: flag batch, review wet-lab protocol, possibly drop/re-run subset.

Implementation: Code Examples

Baseline Computation and Anomaly Detection

Here's the core Python implementation for computing baselines and detecting anomalies: 

import pandas as pd
import numpy as np

Z_THRESHOLD = 3.0

def compute_baselines(qc_history: pd.DataFrame):
    """
    Compute robust baselines (median and MAD) for each metric group.
    
    Args:
        qc_history: DataFrame with columns [assay_type, pipeline_step, 
                   metric_name, metric_value]
    
    Returns:
        DataFrame with baselines (median, mad) per group
    """
    baselines = []
    grouped = qc_history.groupby(["assay_type", "pipeline_step", "metric_name"])
    
    for (assay, step, metric), df in grouped:
        values = df["metric_value"].dropna().values
        if len(values) < 20:
            continue  # not enough history yet

        median = np.median(values)
        mad = np.median(np.abs(values - median)) or 1e-6  # avoid zero

        baselines.append({
            "assay_type": assay,
            "pipeline_step": step,
            "metric_name": metric,
            "median": median,
            "mad": mad
        })
    
    return pd.DataFrame(baselines)

def detect_anomalies(qc_new: pd.DataFrame, baselines: pd.DataFrame):
    """
    Detect anomalies in new QC metrics using robust z-scores.
    
    Args:
        qc_new: New QC metrics to check
        baselines: Baseline statistics from compute_baselines()
    
    Returns:
        DataFrame of detected anomalies
    """
    merged = qc_new.merge(
        baselines,
        on=["assay_type", "pipeline_step", "metric_name"],
        how="left"
    )

    def score(row):
        if pd.isna(row["median"]):
            return np.nan
        z = (row["metric_value"] - row["median"]) / (1.4826 * row["mad"])
        return z

    merged["z_score"] = merged.apply(score, axis=1)
    merged["is_anomaly"] = merged["z_score"].abs() > Z_THRESHOLD
    
    return merged[merged["is_anomaly"]]

Rule-Based Explanation and Remediation

The agentic layer uses domain knowledge to map anomalies to causes and actions: 

RULES = [
    {
        "metric_name": "pct_mapped",
        "condition": lambda row: row["metric_value"] < 60,  # arbitrary example
        "likely_cause": "Low mapping rate; potential reference mismatch or contamination.",
        "recommendation": "Verify reference genome/build, check sample sheet integrity, and re-run alignment if misconfiguration is found."
    },
    {
        "metric_name": "duplication_rate",
        "condition": lambda row: row["metric_value"] > 0.8,
        "likely_cause": "High duplication suggests library complexity issues.",
        "recommendation": "Review library prep batch and consider excluding or re-sequencing affected samples."
    },
    {
        "metric_name": "pct_rRNA",
        "condition": lambda row: row["metric_value"] > 0.3,
        "likely_cause": "High rRNA content suggests failed rRNA depletion.",
        "recommendation": "Flag batch, review wet-lab protocol, possibly drop/re-run subset."
    },
    # Add more rules as needed
]

def explain_and_recommend(anomalies: pd.DataFrame):
    """
    Generate explanations and remediation recommendations for anomalies.
    
    Args:
        anomalies: DataFrame of detected anomalies
    
    Returns:
        DataFrame with explanations and recommendations
    """
    explanations = []
    
    for _, row in anomalies.iterrows():
        for rule in RULES:
            if row["metric_name"] == rule["metric_name"] and rule["condition"](row):
                explanations.append({
                    "sample_id": row["sample_id"],
                    "batch_id": row.get("batch_id"),
                    "assay_type": row["assay_type"],
                    "pipeline_step": row["pipeline_step"],
                    "metric_name": row["metric_name"],
                    "metric_value": row["metric_value"],
                    "z_score": row["z_score"],
                    "likely_cause": rule["likely_cause"],
                    "recommendation": rule["recommendation"],
                    "tool_name": row.get("tool_name"),
                    "tool_version": row.get("tool_version")
                })
                break
    
    return pd.DataFrame(explanations)

Putting It All Together

Here's how you'd orchestrate the full system: 

def run_qc_agent(qc_history_path: str, qc_new_path: str, output_path: str):
    """
    Main function to run the QC anomaly detection agent.
    
    Args:
        qc_history_path: Path to historical QC metrics
        qc_new_path: Path to new QC metrics to check
        output_path: Path to save anomaly report
    """
    # Load data
    qc_history = pd.read_csv(qc_history_path)
    qc_new = pd.read_csv(qc_new_path)
    
    # Compute baselines
    print("Computing baselines from historical data...")
    baselines = compute_baselines(qc_history)
    
    # Detect anomalies
    print("Detecting anomalies...")
    anomalies = detect_anomalies(qc_new, baselines)
    
    # Generate explanations and recommendations
    print("Generating recommendations...")
    recommendations = explain_and_recommend(anomalies)
    
    # Save report
    recommendations.to_csv(output_path, index=False)
    
    # Optionally: generate markdown report
    generate_markdown_report(recommendations, output_path.replace('.csv', '.md'))
    
    return recommendations

def generate_markdown_report(recommendations: pd.DataFrame, output_path: str):
    """Generate a human-readable markdown report."""
    with open(output_path, 'w') as f:
        f.write("# QC Anomaly Detection Report\n\n")
        f.write(f"Generated: {pd.Timestamp.now()}\n\n")
        f.write(f"Total anomalies detected: {len(recommendations)}\n\n")
        
        for _, rec in recommendations.iterrows():
            f.write(f"## Sample: {rec['sample_id']}\n\n")
            f.write(f"- **Batch:** {rec.get('batch_id', 'N/A')}\n")
            f.write(f"- **Pipeline Step:** {rec['pipeline_step']}\n")
            f.write(f"- **Metric:** {rec['metric_name']} = {rec['metric_value']:.2f}\n")
            f.write(f"- **Z-Score:** {rec['z_score']:.2f}\n")
            f.write(f"- **Tool:** {rec.get('tool_name', 'N/A')} {rec.get('tool_version', '')}\n\n")
            f.write(f"**Likely Cause:** {rec['likely_cause']}\n\n")
            f.write(f"**Recommendation:** {rec['recommendation']}\n\n")
            f.write("---\n\n")

Integration with Airflow

To integrate this into your existing pipeline, you can add a task at the end of your DAG:

from airflow.operators.python import PythonOperator

Future Enhancements

Once v1 is working, you can enhance it with:

  • ML-based detection: Use IsolationForest or autoencoders for more sophisticated anomaly detection
  • LLM integration: Use an LLM to generate more nuanced explanations and recommendations
  • Batch-level analysis: Compare entire batch distributions against historical patterns
  • Automated remediation: Automatically trigger reruns or parameter adjustments for certain anomaly types
  • Multi-assay support: Extend to other omics types (WGS, ATAC-seq, etc.)

Conclusion

This autonomous QC system provides a practical, implementable v1 that adds real value to production omics pipelines. By learning baseline behavior and automatically flagging anomalies with actionable recommendations, it reduces debugging time and prevents silent QC failures. The modular design makes it easy to extend and enhance as you gather more data and refine your rules.

The key to success is starting simple: focus on one assay type, collect the right metrics, and build robust baseline models. Once that's working, the agentic reasoning layer becomes straightforward to add, and you can iterate from there.

Key Takeaways:
  • Use robust statistics (median, MAD) for baseline computation
  • Start with rule-based explanations; add ML/LLM later
  • Integrate seamlessly into existing pipelines
  • Focus on actionable recommendations, not just detection
